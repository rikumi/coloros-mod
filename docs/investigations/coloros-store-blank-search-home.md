### 独立 Tab 和位置

- 真实主导航来源 `TabDataPresenter#ނ → StructDto.tabDtoList`，`k7a#֏` 按列表创建 pager，`r3b#ގ` 按相同列表创建菜单。`n3b#ֈ` 独立刷新导航图标模型，因此同样应用可见列表变换。
- 启用后在过滤结果**最前面**增加一个独立 Tab。名称复用 APK `search_text`（简中“搜索”及其原生各语言翻译），ID `0x434d5352` 是明确的模块自有标识，不冒充原生页面 ID。重复输入已含该 ID 时复用并去重，最终只保留一个。
- 原生首页 10、软件 20、游戏 30、榜单 40、我的 50 均保留原 ID 和原 fragment 创建路径；本功能不改名替换任何既有 Tab。
- 原生 `COUINavigationView#getMaxItemCount()` 返回 10，竖向 rail 返回 7；菜单按真实数量测量，增加后的通常六项不需要突破上限或删除原入口。新版浮动导航由 `d82/qj6` 按菜单列表构建。六项在窄屏上的实际观感尚未验收。

### 空白页与搜索入口

- `k7a#Ϳ(TabDto)` 仅对模块 ID 返回一个独立 `EmptyFragment`，在其 arguments 写入持久标记。不是原首页 fragment，也不是搜索 Activity。
- 仅对带标记的 `EmptyFragment#onCreateView` 提供空白容器与原生 `MainActionBar`。普通 EmptyFragment 不受影响。导航图标复用 APK `card_page_main_tab_action_bar_search_icon`，按原生图标回调契约提供 StateListDrawable，未自行绘制图标。
- `MainActionBar` 原生布局为 `card_page_main_tab_actionbar`，其中搜索区域是 `getSearchLayout()`，文字控件为 `SearchWordSwitcher`。使用原生 `byf` 构造器设置文字工厂与点击监听，只显示原生中性提示 `hint_search_no_recomment_word_app=搜索软件`。
- 原生点击链 `byf#ށ → byf#Ԯ → z8e#ԩ → syg(oap://mk/search)`；没有热词对象时以空查询进入真正的搜索流程。本页不调用启动搜索或显示键盘 API，首次进入及返回不会自动弹键盘。
- 不把 byf 加入 lifecycle，因此不启动它的热词订阅和轮播计时；不创建首页、排行、推荐卡片 adapter。空白容器只添加搜索框，隐藏该实例上的语音、AI 和其它侧边入口；其它页面的相同控件不受影响。
- 用户点击搜索框后进入原生搜索界面，输入、联想、结果、下载及更新保留。实际搜索界面的热词/推荐是否隐藏仍由既有 `store_clean_search` 决定；“空白”指新增主导航页，不擅自改变另一独立开关。

## 首页选择、状态恢复与关闭

1. `StructDto` 的可见副本设置 defaultSelected=0。`k7a#֏` 在原生创建 pager 前再设为 0，避免启动参数修改副本后覆盖新增默认首页。原始服务端/磁盘结构不写入新增条目或默认值。
2. `MainTabFragment#onViewCreated`、恢复视图状态之后，以及主界面 `onResume` 后通过原生 `r3b#ޙ(TabID)` 选中搜索。因此冷启动、从独立搜索/详情 Activity 返回主界面及视图状态恢复均有对应处理，不靠自动显示键盘充当首页。
3. 原生 `AnimationFragmentPagerAdapter#getItemId` 返回位置，tag 为 `android:switcher:<viewId>:<itemId>`。直接插入首项会将旧首页错误恢复到搜索位置。实现仅标记主导航的 adapter，将 itemId 改为真实 Tab ID；这个 ID 方案记录在 MainTabFragment arguments 中，跨重建保留，取消搜索后仍能正确复用原生页面。
4. 原生主导航返回回调硬编码 ID 10。启用时仅重定向该主导航回调到搜索 ID：其它主导航页返回搜索，在搜索页撤销这层返回处理，继续由系统/Activity 原生处理退出。原首页内部分类/子页自己的返回层级保留。
5. 用户改变开关后回到商店时，若页面记录的模式不同，仅重建当前 Activity 一次，由原生菜单和 pager 一起重建；不是进程重载。关闭时不再插入搜索，移除恢复状态中残留的带标记搜索 fragment，并按原始结构及当前其它隐藏设置恢复默认选择。没有修改持久商店数据。
6. 用户正常点击其它主导航项不会被永久锁回搜索；仅初始化、状态恢复、主界面重新 resume 和主导航“返回首页”路径选择搜索。原首页分类模式的触摸限制不会标记这个独立 fragment/pager。

## 组合行为

| 组合 | 代码行为 |
|---|---|
| 隐藏首页 | 原首页 10 去除，搜索仍位于第一项并作为默认页 |
| 隐藏游戏、榜单及任意组合 | 先按原 ID 过滤，再加搜索；不因原生列表顺序变化丢失搜索 |
| 软件页 | 当前项目没有独立“隐藏应用/软件 Tab”开关，不虚构偏好。软件 20 保持现行行为；服务端列表不包含软件时也不影响新增搜索 |
| 首页顶部只保留分类 | 只处理原 HomeSubTabPresenter；搜索页不使用该 presenter，不会被替换成分类或清空 |
| 去除首页与软件页推荐内容 | 搜索页没有首页推荐 adapter，始终仅有搜索入口；原首页内容按原开关处理 |
| 搜索净化关闭/开启 | 新增主导航页始终无热词/推荐；点击进入真正搜索页后，按原搜索净化开关决定空查询页内容 |
| 禁用动态图标/特殊应用样式 | 新导航图标是原生静态资源；搜索框不创建应用资源模型，互不依赖 |
| 新增搜索关闭 | 不加搜索，原生默认选择与其它净化开关继续工作；不会自动打开搜索或键盘 |
